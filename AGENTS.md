# AGENTS.md

Two independent apps in one repo, no monorepo tooling shared between them:

- `backend/` — Strapi v5 (headless CMS), runs on **:1337**, SQLite (better-sqlite3)
- `frontend/` — Next.js 16 (App Router), runs on **:3000**, talks to Strapi via `STRAPI_BASE_URL`

Package manager is **pnpm** (`packageManager` pinned to pnpm@11.3.0). Both dirs have their own `pnpm-workspace.yaml` but they are NOT linked; install/run commands run separately per directory.

## Setup & run

```bash
# backend
cd backend && pnpm install   # builds better-sqlite3/esbuild/sharp (allowlisted in pnpm-workspace.yaml)
cp .env.example .env         # required before first run
pnpm dev                     # strapi develop → http://localhost:1337/admin

# frontend
cd frontend && pnpm install
# needs .env with STRAPI_BASE_URL=http://localhost:1337 (already present)
pnpm dev                     # next dev → http://localhost:3000
```

Both must run together. Frontend calls `STRAPI_BASE_URL` (server-side `lib/api.ts`), not `NEXT_PUBLIC_*`.

## Commands

- Backend: `pnpm dev` (develop w/ reload), `pnpm build` (admin panel), `pnpm start`, `pnpm strapi <cmd>`, `pnpm upgrade:dry` (dry-run upgrade).
- Frontend: `pnpm dev`, `pnpm build`, `pnpm start`, `pnpm lint` (ESLint 9 flat config in `eslint.config.mjs`; no typecheck script — Next runs `tsc` during `build`).

## Architecture / conventions

- **Strapi content-types are code-generated, not hand-written.** Models live under `backend/src/api/<name>/content-types/<name>/schema.json`. Editing schema fields by hand is fragile; prefer `pnpm strapi` generators. The `Cliente` entity uses `documentId` (string) as the API identifier, not numeric `id`.
- **Frontend auth is cookie-based (HTTP-only JWT).** Route protection is a custom middleware in `frontend/proxy.ts` (`/dashboard` matcher) that calls `GET /api/users/me` and redirects to `/signin` on failure — not Next's middleware file name. Don't replace it with a different mechanism without checking `proxy.ts`.
- **Server Actions** live in `frontend/actions/` (`auth.ts`, `mutations.ts`); they call `lib/login-register.ts` and `lib/endpoint-api.ts`, never fetch Strapi directly from a component.
- **React Query** (`@tanstack/react-query`) handles client data; `useClients` is opt-in (`enabled: false`) — it must be triggered manually, not on mount.
- Forms validated with **Zod** (`validations/`). Form components use `sing-in`/`sing-up` spelling (matching existing files) — keep that spelling in new files.

## Gotchas

- `backend/.env` is required and **not** generated by install; copy from `.env.example` or Strapi won't boot.
- SQLite is dev-only; the repo warns to use PostgreSQL for prod. Don't add migration SQL by hand — Strapi manages `database/migrations/` from schema changes.
- `better-sqlite3`/`sharp`/`esbuild` need native builds; the backend `pnpm-workspace.yaml` `onlyBuiltDependencies` allowlist is what permits `pnpm install` to succeed. If install skips builds, that list is the cause.
- Next 16 + React 19: App Router only. No `pages/` directory.
